# 成本估算

两种成本要分开看：**开发/维护成本**（一次性）和 **运行成本**（每场考试）。

## 一、运行成本（每场考试）

假设一场 20 题单选，走「题库优先 → LLM 兜底」，题库命中率 0%。

### Token 估算（每题）

| 项 | 单选 | 简答 |
|---|---|---|
| system prompt | ~200 | ~200 |
| 题干 + 5 选项 | ~120 | ~150 |
| 输出（JSON 或作答文本） | ~60 | ~450（150 字左右） |
| 合计 | **~380 token** | **~800 token** |

20 题：约 **7.6k token**（输入 5.2k / 输出 2.4k）。

### 单价（以 DeepSeek 官方价为量级参考，¥/百万 token）

| 模型档 | 输入（缓存未命中） | 输出 | 20 题成本 |
|---|---|---|---|
| deepseek-chat（便宜档） | ¥2 | ¥3 | 5.2k×2/1e6 + 2.4k×3/1e6 ≈ **¥0.018** |
| 中档推理模型（假设 ¥4 / ¥12） | ¥4 | ¥12 | ≈ **¥0.05** |
| 一线闭源模型（¥30 / ¥120 量级） | ¥30 | ¥120 | ≈ **¥0.45** |

> 结论：**一场考试几分钱到几毛钱**。题库命中时是 0 元。
> 提示词全部是「新内容」，缓存命中率低；同一个模型多次请求同一题才能吃到缓存折扣。

### 其它运行成本

| 项 | 量级 |
|---|---|
| 题库存储 | chrome.storage.local 5–10MB，约 **1–2 万条**题干；免费 |
| 网络请求 | 20 次 HTTPS POST，可忽略 |
| CPU | 归一化 + Dice 匹配，1 万条题库单题 < 20ms |

## 二、开发成本（一次性）

以「功能完整、能上 GitHub」为口径：

| 模块 | 代码量 | 人力 |
|---|---|---|
| MV3 骨架 + 面板 UI | ~400 行 | 0.5 天 |
| 超星 DOM 适配（多选择器兜底） | ~250 行 | 1–1.5 天（**主要成本在版本适配**） |
| 题库 + 模糊匹配 + 导入导出 | ~300 行 | 1 天 |
| 去水印归一化 | ~120 行 | 0.5 天 |
| 拟人输入 / 节奏 | ~120 行 | 0.5 天 |
| LLM 兜底 + prompt | ~150 行 | 0.5 天 |
| 设置页 / 弹窗 | ~350 行 | 0.5 天 |
| 文档 / 打包 / 发布 | —— | 0.5 天 |
| **合计** | **~1700 行** | **5–6 人天** |

本仓库这一次由 AI 直接产出，实际耗时约 **30 分钟**（含我排查 DPI / 权限环境问题），
留给你的主要是：**在若干门课的真题页面上把 `SEL` 选择器校准一遍**（每套页面 10–20 分钟）。

## 三、规模化成本（如果你要做成产品）

| 项 | 说明 |
|---|---|
| 题库服务器 | 一万题约 2MB JSON，对象存储 + CDN 基本 0 成本 |
| 代理池（若做题库 API 聚合） | ¥1–5/千次请求 |
| 推理端点 | 自建 8B 模型一台 4090 足够，¥0.002/题量级 |
| 发布 | Chrome 商店开发者账号 $5 一次性；Edge 商店免费 |

## 四、省钱技巧

1. **先攒题库**：把 `LLM 结果写回题库` 打开，同一门课第二遍几乎 0 成本。
2. **简答单独降级**：简答用便宜模型，选择/判断用强模型 —— 选择题目标题短，弱模型也够。
3. **答完即抛**：`llmCache` 只在当前页面生命周期内有效，避免长会话上下文膨胀。
4. **题干截断**：超过 400 字的题干只送前 400 字，几乎不影响命中率却省一半 token。
